## Local development sign-in — 2026-10-19

Vite now supplies loopback-only local admin endpoints when the ignored `.cache/local-admin.json` contains a password. The user-requested local credential is configured on this machine; never put its value in docs, tracked source, client env variables or commits. The Vite configureServer hook reads it server-side; production builds never load that config or expose those endpoints. Remove/rename this local config and restart Vite to use the normal root API proxy instead.

Local sessions use random server-memory tokens, a separate HttpOnly/SameSite=Strict cookie, one-hour expiry and logout revocation. Login has bounded body size, five attempts per10min and loopback host/address plus origin checks. Server restarts invalidate sessions. Orders return an explicitly identified empty local workspace and cannot mutate live records. A development-only link opens fictional design samples. The setup instruction was removed from automatic session-check errors; failed attempted sign-in still gets a useful error. Actual local sign-in/reload/logout verified; Vercel still requires ADMIN_PASSWORD/server secrets and normal backend acceptance, unchanged by this local helper. This section supersedes the earlier Vite-only limitation below.

`/admin` is a lazy route outside ShinobiLayout, with its own scoped a- CSS and existing DM Sans/Archivo Black fonts. No storefront motion/header/cart/footer is mounted here.
